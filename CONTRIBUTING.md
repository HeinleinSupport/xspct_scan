# Contributing

## Commit messages

Starting with the release **after `0.5.2`**, this project uses
[Conventional Commits](https://www.conventionalcommits.org/en/v1.0.0/) for
all commit messages. Commits made before that cutover follow an older,
informal `[Tag] Description` convention and have **not** been rewritten
retroactively — see `docs/changelog.md` for the marked cutover point.

### Format

```
<type>(<scope>): <description>

[optional body]

[optional footer(s)]
```

### Types

| Type | When to use |
|------|-------------|
| `feat` | New functionality |
| `fix` | Bug fix |
| `docs` | Documentation only |
| `refactor` | Restructuring without behavior change |
| `test` | Test-only change |
| `perf` | Performance improvement |
| `build` | Build system, dependencies, `pyproject.toml` |
| `ci` | CI configuration |
| `chore` | Other maintenance |

### Scopes

| Scope | Area |
|-------|------|
| `api` | HTTP endpoints, request/response formats |
| `analyzer` | Individual analyzer modules |
| `verdict` | Scoring and verdict logic |
| `cache` | Redis result cache |
| `client` | CLI client |
| `config` | Configuration schema and defaults |

### Breaking changes

Mark with `!` after the scope (e.g. `feat(api)!: ...`) and/or a
`BREAKING CHANGE:` footer.

### Rules

- Description in the imperative mood, lowercase, no trailing period.
- First line at most 72 characters.
- Body is optional, separated from the header by a blank line.
- **All commits and tags must be GPG-signed:**
  ```bash
  git commit -S -m "feat(api): add multipart metadata part"
  git tag -s X.Y.Z -m "Tag message"
  ```
- **Never** include "generated by", "co-authored by", or any AI attribution
  in commit messages.
- Independent changes are committed separately — don't mix an analyzer
  extension with an API change in the same commit.
